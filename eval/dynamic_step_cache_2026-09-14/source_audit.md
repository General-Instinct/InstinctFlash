# DreamZero dynamic step-cache source audit

Source SHA-256 values and audited line ranges are retained in the [source bindings](source_audit.json). The original checkout paths in that JSON are provenance; the [framework comparison guide](../../benchmarks/regression/FRAMEWORK_COMPARISON.rst) describes the pinned dependency setup. Source-binding links below identify the audited files without requiring the author's directory layout.

Audited 2026-09-14 from local sources and retained receipts. No GPU jobs or worker operations. The pinned Omni commit is `f7d9deb45ab56e6a2ccc1690279bd9e6bdefbfe3`; the audited Omni files are clean against that commit. [source_audit.json](source_audit.json) records every source path, SHA256, line range and detailed recommendation. The recorded Thor compatibility patch changes startup handling only.

**The default skip rule matches, but end-to-end equivalence and speed attribution are not established.** Both implementations compare the last two *computed* CFG-combined video velocities, using `flatten(1).float()`, cosine similarity along dimension 1, then a batch mean. Strict `>0.95` starts four skipped slots and strict `>0.93` starts two. A burst includes its triggering slot; countdown expiry forces one recompute if another scheduler slot exists. A new skip burst may start immediately afterward.

The native history entry is `(timestep, video_CFG, action_cond)`, so the comparison tensor is entry **[1]**. Omni's history entry is `(video_CFG,)`, so it is **[0]**; the latest conditional action is stored separately. This tuple normalization is required for a parity test. Sources: [native rule source binding](source_audit.json), [Omni rule source binding](source_audit.json).

**A skip reuses the full latest video/action output pair.** The signal is video after `negative + cfg_scale*(positive-negative)`; the action is positive/conditional only and does not participate in admission. Both schedulers still execute every original sampling slot. Neither implementation extrapolates the cached result here: native `cache_predict_order1` exists but is not called by the skip branch. Sources: [native loop source binding](source_audit.json), [Omni CFG coupling source binding](source_audit.json), [Omni loop source binding](source_audit.json).

**The lifetime is one generation, separate from session KV caches.** Native empties history and resets its countdown before each denoise loop. Omni creates fresh prediction history/payloads in `diffuse`, while the countdown lives on the pipeline. Normal request execution calls runner refresh before `pipeline.forward`; `StepCacheBackend.refresh` resets that countdown. Direct repeated calls to `diffuse` bypassing the runner do not provide the same reset guarantee. Autoregressive KV, prompt embeddings, CLIP and VAE streams have separate session/window lifetimes. Observation/KV prefill runs outside the skip loop. Sources: [native reset source binding](source_audit.json), [runner refresh source binding](source_audit.json), [backend reset source binding](source_audit.json), [prefill source binding](source_audit.json).

**Current benchmark configuration is known; actual saved DiT calls are unknown.** The retained September 13 Omni cell requests compilation, BF16, 16 sampler slots, CFG 5, shift 5, seed 1140, horizon 24, and the default `[0.95,0.93] / [4,2]` step-cache configuration. It runs one GPU, one request at a time, with sequential positive/negative CFG. There are 33 requests: 3 warmup plus 30 measured, with an explicit reset every three-call session. One recomputed denoise slot therefore executes two branch transformer forwards; the observation prefill contributes an additional CFG pair. The receipt and available log do not retain per-request skip masks or actual call counters. **Do not infer four computed slots or identical native/Omni skip patterns from timing or thresholds.** Sources: [deployment source binding](source_audit.json), [benchmark](../framework_comparison_2026-09-13/benchmark_omni_dreamzero_v4.py#L37), [retained receipt](../framework_comparison_2026-09-13/receipts/omni-dreamzero-compiled-v1.json).

**Guardrails are limited.** First-two-history initialization, countdown expiry, cached-output availability and Omni's output clones protect execution mechanics. There is no mandatory final-slot recompute, no action error bound and no explicit finite-payload admission. Similarity is averaged across batch samples. Dynamic mode replaces the native fixed mask; it can compute more than the fixed eight-of-sixteen policy if similarity is low. The pinned config converter only checks equal threshold/countdown list lengths: invalid minimum history, history capacity or nonpositive countdowns need validation in a shared API. These are future API concerns; the pinned default parameters are internally consistent.

**Prior claims and their corrections:** The old `step_cache.py` text is frozen in [research/prior_step_cache.py](research/prior_step_cache.py) and bound separately from the corrected current file.

- `examples/dreamzero/step_cache.py` may say the *default decision rule* is shared. It should not imply the frameworks execute identical skip patterns or have identical persistent caches and preprocessing.
- The historical native pair is **3116.5 → 1786.6 ms**, with a 12-request action-output screen (maximum absolute delta 0.2880859375, mean about 0.0319688424). That is historical native fixed-mask versus dynamic evidence; it is neither the current Thor result nor an Omni ablation.
- The historical Omni **1123.8 ms / 2.77×** comparison used a different observation contract. Both cache and compilation were enabled, but no retained same-input cache/compile ablation assigns their separate gains. Remove the claim that the remaining gap is compiled kernels.
- Historical `stock.json` reports **1843.1 ms** under a stock label, but its associated log identifies a dynamic run. Keep it separate from the 1786.6 ms paired capture and do not use its filename as evidence of the baseline.
- Approximate reuse *can* change outputs, and this screen did; it does not guarantee every input changes. `serving_env()` only copies the environment and sets one variable, without counters or quality admission.

**Recommended shared API:** immutable validated policy plus a generation-owned state with explicit `begin_generation`, decision, and computed-output recording. Let the adapter select the comparison tensor and coupled output schema; DreamZero uses video-after-CFG to decide reuse of video-after-CFG plus conditional action. Preserve every scheduler slot and keep prefill/KV commits outside the cache. Own retained tensors, validate shape/dtype/device/finiteness, and reset on new generation or failure. Endpoint recomputation or action-sensitive gates would be distinct policies requiring their own qualification. Emit sampler slots, compute/skip reasons, similarity, stale age, CFG branch calls and prefill calls separately in bound receipts. Dynamic reuse requires explicit **BEHAVIORAL permission**. Its current quality evidence is **SCREEN**; evidence status is independent of execution permission. Keep it separate from exact tensor-cache admission.
