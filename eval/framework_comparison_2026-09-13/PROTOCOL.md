# Framework comparison protocol — Jetson Thor

This is the intended quality-constrained selection protocol. The current [eight-model, three-framework matrix](measured_candidates.md) completes speed coverage only; it is not the final admitted ranking. Pending quality gates and independent winner confirmations must complete before making that claim. [Quality admission](quality_admission_inventory.json) remains separate.

Compare all eight InstinctFlash model families on one Jetson Thor. Per user scope change, H100 measurements are retained only as exploratory records and are excluded from the final comparison. No further H100 benchmark jobs are scheduled.
Primary table selects one fastest **quality-admitted** configuration per model and framework on Thor. Native precision, NUMERIC, FP8, distillation, CFG changes and step changes all compete under the same quality constraint. Do not prefer or exclude a route because of its technique. Record the winning checkpoint/revision, precision, CFG, sampler/grid, full action horizon and measured p50. Keep all losing, failed and unqualified candidates in the evidence archive rather than duplicating rows in the primary table.

Quality acceptance follows each model's **existing quality acceptance standard**, as explicitly selected by the user. Do not introduce a new universal success-rate-loss threshold or retroactively change existing metrics, margins or confidence rules. For each model, record its governing acceptance artifact/protocol, metric, reference configuration, threshold and confidence rule (where applicable), and whether each candidate passes. Apply that model's rule consistently across framework candidates. If no existing acceptance rule or matching evidence can be found, mark admission pending rather than inventing a pass.

Reuse existing quality evidence only when its checkpoint/weights, precision, sampler/grid, CFG, input/action contract and evaluation scope match the candidate being timed. A latency result or finite-action check alone does not establish quality admission. Respect the limitations of existing numerical screens, historical open-loop analyses and closed-loop certificates rather than treating them as interchangeable. In particular, Cosmos historical UniPC4/CFG4/shift1 controls are not the official default UniPC4/CFG3/shift5 reference; the existing negative quality findings must remain visible.

Single-GPU execution throughout. Select on p50 among admitted candidates and confirm the winner in a separate run before ranking; never select individual minimum-latency calls. Never substitute pi0 for pi05 or video generation for action prediction.

Timing is synchronized wall time for an observation to fresh actions, including preprocessing and postprocessing. Queue-only calls are excluded. Setup is separate. Record p50/p95/p99, raw samples, full action outputs when available, checkpoint/source revisions, executed schedule and software versions. No task-quality claim follows from latency. Initial runtime screen: 10 warmups + 30 measurements for stateless policies; history policies use complete three-cycle episodes with the first episode discarded and are explicitly early-regime screens. For the final matrix, history models use the 20 continuation calls after warmup to align reset/output boundaries across frameworks; all original timings remain archived. See [history timing alignment](HISTORY_TIMING.md). These short runs do not establish tail-latency guarantees.
